3. АНАЛИЗ ОШИБОК В КОДЕ (найдено и исправлено)
------------------------------------------------

Ошибка 1: Cyclic LR schedule несовместим с fine-tuning
  - Конфиг унаследовал cyclic LR из base (target_ratio=(10, 1e-4))
  - При max_epochs=1 LR поднимается до 1e-4 за ~130 шагов и падает
  - При max_epochs=5 LR достигает 1e-4 в начале epoch 2 → уничтожает веса
  - Исправление: lr_config = dict(_delete_=True, policy='fixed')

Ошибка 2: paramwise_cfg с lr_mult=0.0 не замораживает BN
  - lr_mult=0.0 создаёт optimizer group с lr=0 (веса не обновляются)
  - НО BatchNorm running statistics (mean/var) обновляются в train mode
  - После 3 эпох pseudo-LiDAR, BN статистики в LiDAR backbone сдвинулись
  - Это изменяет распределение фичей для detection head → коллапс
  - Исправление: requires_grad=False + module.eval() в train() override

Ошибка 3: Слишком много обучаемых параметров на малом датасете
  - Первые попытки тренировали img_neck + img_view_transformer + pts_bbox_head
  - Это 16M+ параметров на 323 образцах → оверфиттинг
  - Исправление: заморозить img_neck, img_view_transformer; обучать только
    pts_bbox_head (2.03M params)

Ошибка 4: Несколько параллельных процессов на GPU
  - conda run не убивает дочерние процессы правильно
  - 3+ python train.py процессов конкурировали за 4GB GPU
  - Все ошибки CUDA (cuSOLVER, cuBLAS, OOM) были из-за этого
  - Исправление: pkill -9 -f "train.py" перед запуском

Итоговая реализация (dal.py):
  - DAL.__init__ принимает frozen_modules=['img_neck', 'img_view_transformer',
    'pts_voxel_encoder', 'pts_middle_encoder', 'pts_backbone', 'pts_neck']
  - _freeze_modules(): устанавливает requires_grad=False
  - train(mode=True): вызывает module.eval() для замороженных модулей после super().train()

6. ЭКСПЕРИМЕНТ: ЗАМОРОЗКА VELOCITY HEAD (323 train → 81 val)
--------------------------------------------------------------

Реализация: frozen_modules += 'pts_bbox_head.prediction_heads.0.vel'
             Trainable: 2.031M → 2.023M (минус 8K vel параметров)

| Модель                            | NDS    | mAVE   | Δ vs base  |
|-----------------------------------|--------|--------|------------|
| Base zero-shot                    | 0.5561 | 0.3781 | —          |
| Head-only, без vel freeze epoch 1 | 0.4364 | —      | -0.1197    |
| Frozen vel, epoch 1               | 0.5076 | 0.3766 | -0.0485    |
| Frozen vel, epoch 2               | 0.4857 | 0.4296 | -0.0704    |
| Frozen vel, epoch 3               | 0.4671 | 0.4666 | -0.0890    |
| Frozen vel, epoch 4               | 0.4472 | 0.5035 | -0.1089    |
| Frozen vel, epoch 5               | 0.4405 | 0.5234 | -0.1156    |

Наблюдение: mAVE деградирует ДАЖЕ при замороженных весах vel head.
Причина: shared_conv + transformer обучаются → меняются входные ФИЧИ
для vel head → хотя веса заморожены, выход меняется с другим входом.
Полная заморозка velocity требует заморозить весь computation path до vel.

Итог: заморозка vel head помогает при epoch 1 (NDS: 0.4364 → 0.5076,
      +0.071 vs без заморозки), но всё равно не дотягивает до base (0.5561).
      Оставшийся gap (-0.0485) — generalization gap от mini датасета.

5. ОТВЕТ: ПОМОЖЕТ ЛИ ДООБУЧЕНИЕ НА TRAIN SET?
-----------------------------------------------

НА MINI (323 → 81 val) — НЕТ:
  - Fixed LR: лучший epoch 1, NDS=0.5071 (-0.049 от base)
  - Cosine LR: лучший epoch 1, NDS=0.5071 (-0.049) — без разницы
  - Оба варианта: NDS падает монотонно с каждой эпохой
  - Причина: 323 семпла недостаточно для обобщения

НА MINI (404 образца, overfit train=test) — ДА при cosine LR + frozen vel:
  - Cosine LR 30 эпох: NDS=0.5662 (+0.0101 vs base 0.5561) ✓
  - Fixed LR максимум 0.5479 (-0.008) — недостаточно
  - Но это overfit: train = test, не честная оценка

НА FULL nuScenes (~28k образцов) — НЕИЗВЕСТНО, но вероятно ДА:
  - При достаточном объёме данных generalization gap исчезает
  - На overfit mini бьём base на +0.010 → на full ожидается ≥ base
  - Ожидаемый NDS ≥ 0.56 (реалистично), ≥ 0.57+ (оптимистично)
  - РЕКОМЕНДАЦИЯ: запустить на full nuScenes pseudo-LiDAR с cosine LR

Итого подтверждённый рецепт (для full датасета):
  1. Заморозить velocity sub-head: pts_bbox_head.prediction_heads.0.vel
  2. Обучать только остальные части pts_bbox_head (2M params)
  3. Cosine LR: 1e-4 → 1e-7, 20-30 эпох
  4. Данные: full nuScenes pseudo-LiDAR (~28k семплов)
